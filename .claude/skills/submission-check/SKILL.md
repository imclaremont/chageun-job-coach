# 제출 전 점검

대회 규정 요약은 `docs/contest.md`에 있다. 아래를 순서대로 확인하고, 항목마다 통과·실패·확인 불가를 근거와 함께 보고한다. 확인하지 못한 항목을 통과로 적지 않는다

## 1. 코드 상태

```bash
npm run check
npm run build
git status --short
```

- 셋 다 깨끗해야 한다

## 2. 비밀 정보

```bash
git grep -nE "sk-[A-Za-z0-9_-]{20,}|AKIA[0-9A-Z]{16}|AIza[0-9A-Za-z_-]{35}|BEGIN [A-Z ]*PRIVATE KEY" -- . ':!package-lock.json'
git log --all --oneline --diff-filter=A --name-only | grep -E "(^|/)\.env" | grep -v "\.env\.example"
```

- 두 명령 모두 결과가 없어야 한다
- 시연 영상과 발표자료 화면에 키가 보이지 않는지는 사람이 확인한다

## 3. 개인정보

- 시드 데이터와 화면 예시가 전부 가상 데이터인지 확인한다
- 외부 AI로 보내는 프롬프트에 실제 개인정보가 들어갈 경로가 없는지 확인한다

## 4. 프로토타입 접근

- 배포 주소를 로그인하지 않은 브라우저(시크릿 창)에서 연다
- 코치 흐름(매뉴얼 입력 → AI 변환 → 승인)과 근로자 흐름(단계 수행 → '잘 모르겠어요' 코칭)을 끝까지 실행한다
- AI 호출이 실제로 성공하는지 확인한다
- OpenAI 사용량 한도와 결제 수단이 2026-12-07까지 유지되는지는 사용자에게 확인을 요청한다

## 5. 출처와 라이선스

- `package.json`의 의존성과 `docs/credits.md`를 대조해 빠진 항목이 없는지 확인한다
- 외부 데이터·이미지·폰트·API가 모두 적혀 있는지 확인한다
- README에 Credits / Licenses 섹션이 있는지 확인한다

## 6. AI 활용 표시와 기록

- AI가 만든 내용에 화면에서 AI 생성 표시가 붙어 있는지 확인한다
- `docs/ai-usage-log.md`가 최신인지 확인하고, 이를 바탕으로 제출서의 「AI 활용내역」(3,000자 이내, 4개 항목) 초안을 점검한다
  1. 활용 AI 모델·도구 (서비스용과 개발용 구분)
  2. AI 활용 범위와 팀의 기여
  3. API·외부 데이터·오픈소스
  4. 검증 및 한계 대응

## 7. 제출 서류 — 사람이 최종 확인

- 프로젝트 소개서 PDF: 본문 10장 이내, 작성 안내 페이지 삭제, 지정 별첨(팀 구성, 기존 개발물·사전 개발 내역, 외부 자원·출처) 작성
- 기존 개발물과 타 공모전 출품 여부는 사실대로 적는다. 소개서 별첨과 제출 설문의 내용이 서로 같아야 한다
- 파일명: `[팀명]_프로젝트명_AI 해커톤_제출일자`
- 제출 링크 업로드 후 같은 자료를 korcham.careerfair@gmail.com 으로 발송, 메일 제목: `[팀명]_프로젝트명_AI 해커톤_제출일자 / 과제제출`
- 마감: 2026-11-23(월) 17:00 KST, 마감 직전 접속 몰림을 피해 여유를 둔다

## 8. 버전 고정

- `main`에 릴리즈가 머지되고 태그가 달렸는지 확인한다
- 제출 시점의 태그와 커밋 해시를 보고에 적는다

```bash
git fetch --tags && git log -1 --format="%H %s" main && git tag --points-at main
```
