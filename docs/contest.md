## 개발에 영향을 주는 규칙

- **AI 도구 사용은 전면 허용**: 코드 생성 비율 제한이 없다. 대신 AI가 한 일과 팀이 한 일을 구분해 공개해야 하고, 팀원이 작동 원리와 오류 대응을 설명할 수 있어야 한다
- **마감 후 변경 금지**: 기능·알고리즘·프롬프트·데이터를 바꿀 수 없다. 접속 복구·인증정보 교체·실행 환경 복구만 허용되고, 변경 내용과 사유를 운영사무국에 알리고 이력을 남긴다
- **프로토타입 유지**: 2026-11-30까지, 본선 진출 시 2026-12-07까지 정상 작동해야 한다. API 사용량 한도와 과금 설정을 점검한다
- **개인정보**: 동의 여부와 관계없이 외부 AI 서비스에 실제 개인정보·민감정보를 보낼 수 없다. 가상·샘플 데이터만 쓴다
- **보안**: API 키·비밀번호·토큰을 코드·영상·발표자료에 노출하지 않는다
- **출처**: 오픈소스·데이터·이미지·폰트·API는 라이선스를 확인하고 출처를 적는다. 저장소를 제출하면 README에 Credits / Licenses 섹션을 둔다
- **AI 표시**: 서비스 화면에서 AI가 생성한 내용임을 알 수 있게 표시할 것을 권장한다
- **기존 개발물**: 해커톤 이전에 만든 코드·모델·기획물을 쓸 수 있지만 종류·시기·범위를 사실대로 적어야 한다. 평가는 2026-11-09 10:00부터 마감까지 새로 만들거나 실질적으로 개선한 부분이 중심이다
- **타 대회 출품작 금지**: 다른 공모전·대회에 출품했거나 수상한 결과물과 같거나 실질적으로 비슷하면 제출할 수 없다. 수정·고도화, 미수상, 출품 철회도 포함한다
- **커밋 이력**: 저장소를 제출하면 커밋 이력을 유지하고 마감 시점 버전을 태그나 커밋 해시로 남길 것을 권장한다
- 위반 시 심사 제외, 수상 취소와 상금 반환, 3년간 참가 제한까지 가능하다

## AI 활용내역 4개 항목

1. 활용 AI 모델·도구 — 서비스용 모델과 개발용 도구를 구분, 가능하면 버전 포함
2. AI 활용 범위와 팀의 기여 — AI가 한 일과 팀이 판단·설계·수정·검증한 일을 단계별로 구분
3. API·외부 데이터·오픈소스 — 주요 명칭과 용도, 해당 없으면 "해당 없음"
4. 검증 및 한계 대응 — AI가 만든 코드·정보의 확인 방법, 주요 오류와 보완, 남은 한계
